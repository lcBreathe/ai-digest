本期导读

团队让Agent修改代码、积累项目技能，往往会沿用一个直觉：重跑旧任务，分数提高，就把新做法留下。技能是给Agent反复调用的任务说明，规则也可能随文件读取自动载入；它们能减少重复纠正，但一次成功还无法说明模型读到了什么，也无法说明原来正确的工作有没有被破坏。本周从技能回放到代码审查，最值得追的就是这些过去藏在“通过”里面的差别。 此前的观察把问题放在外部判据：检查者多一位，并不保证多一份生成者无法控制的证据。Cortex把这个追问推进到指令曝光和配对回放，Claude Code团队又补入已知干净的改动，检查审查意见会不会诱发有害修改。它们提供了更具体的正面办法，也让我们修正一种过快的读法——没有留下有害规则，不一定等于已经识别了伤害。第一篇观察说明这些检查各自能承诺到哪里。 周末的ECDSA曲线种子溯源提供了另一个对照。ECDSA是广泛使用的数字签名方法，一批标准参数长期缺少种子来历；现在可以从旧式伪随机数生成器重算它们，仍不能据此恢复所有弃选记录。它与科研实验的选择偏差不是同一机制，但共同提醒我们：结果能重现以后，还要说清为什么留下这一项。 第二篇观察回到工作交付。PR是一组等待团队审查并合入的代码改动；少几轮审查可能减少返工，也可能只是把缺陷留到以后。周报独立补入的Mercor职业任务图谱，则先问评测有没有测到这些工作：题目覆盖少不等于模型做不了，已有题目得分高也不等于整个岗位已被测过。先读本周总结与两篇观察，再按需要进入四条精选；末尾三个候选想法分别检验验收面板、误报执行后果和任务覆盖的边界，都附近邻与失败判据。

本周总结

本周有几项评估开始把“变好”拆开，也让此前的判断变得更具体。Cortex记录规则是否实际进入上下文，避免把偶然成功归给没人读过的技能；Claude Code团队把干净改动和有害建议放进审查评估，避免只在事故集中优化召回。此前只问多一个检查者能增加什么保证，现在可以具体追问它读到了什么、漏掉什么，又会改坏什么。作者提供了值得借用的设计，跨仓库效果仍没有独立证明。

周末的ECDSA种子溯源则带来一个更强的可核对成果：公开参数与旧式生成器之间出现了具体的数值关系。它收窄了参数来源的猜测，却没有恢复全部选择历史。把这件事与本周回访的InnovationEval并读，更清楚地看到保存结果和保存筛选过程各自的价值；一个是历史资料问题，一个是能从实验设计上预防的选择偏差，不能混写成同一种“模型不可信”。

人力负担的判断也需修正。企业合并等待变长，与某些团队审查变快可以同时成立。自动评论可能制造新修改，可运行复现、风险分层和收敛控制也可能减少工作。评价应同时保留真实缺陷、干净样本、人的实际判断和交付后返工。只数生成行数、评论或审查轮数，都不足以回答同样质量的工作是否更快交付。

独立查漏补入的Mercor职业任务图谱提醒我们先检查分母：一份基准索引覆盖了哪些工作，和模型在这些工作上做得怎样，是两项测量。其“约九成工时缺少覆盖”来自29个所选基准、职业映射与工时估计，并非全网评测普查。已有APEX（Mercor自有办公任务评测）题目重新加权后分数相近，也没有填上未测任务。对研究和工程选题，最有价值的是确定还缺哪一种可执行对照，而不是把覆盖缺口换成确定的失业或能力预测。

编辑观察

一次检查通过，要能说清它排除了什么

本周最值得保留的进展，是“再检查一次”开始变成几种可以分别观察的操作。写给编程 Agent 的技能，是能被反复调用的任务说明；规则则可能在读取特定文件时自动载入。即使两者文字完全正确，也要先知道模型有没有真正接触它们。Cortex 把这个环节记录下来，使一次分数上涨不再自动归功于刚加入的说明。这支持了此前的判断：检查角色和文件数量，都不是新增证据的计量单位。

但有记录仍可能问错问题。Cortex 的有害候选试验主要在原本失败的任务上初筛；一条规则若把原先成功的任务改坏，失败集未必给它显形的机会。这里需要修正的是读法：没有收下有害候选，可能来自没有读到、没有增益或暂未作决定，不能全部算成识别伤害。与此同时，论文正式门槛确实保护一部分旧成功，不能反过来说它完全没有防回归设计。负控试验的诊断能力与系统设计意图，应分别评价。

Claude Code 团队的实践补上一种可行的测量：让审查器看已知干净的改动，检查它会不会提出诱发有害修改的意见。这比只在事故集合上查召回更接近实际使用，因为建议会被下一位 Agent 执行。正面意义是把主动制造错误的机会计入评估；仍未回答的是，干净标签怎样确认，以及内部改进能否迁移到其他仓库。相邻案例提供了办法，没有替 Cortex 完成验证。

科研实验还多一层选择问题。10月11日读到的 InnovationEval 以近期人类后训练方法为参照，让模型提出并实现改进；研究者检查后发现，只报告许多相近运行中的最好一次，会把方法收益抬高。它是少数高成本尝试的初步评估，不足以判定所有科研 Agent 的能力，却说明保留最后代码和最高分仍不够。需要留下每次尝试、选择依据，以及选中以后没有参与挑选的新测量。

周末的曲线种子溯源给了另一种有价值的边界。重建一个旧伪随机数生成器，能严格核对现存数字之间的关系；它没有自动恢复当年所有弃选候选。这里缺的是历史识别信息，和科研实验中的统计偏差并非同一种错误。两者共同要求公开选择过程，但一个需要新的史料，一个可以从现在开始设计独立确认。不能靠重复算出同一数字，补齐本来没有保存的历史。

补查近邻后，也应收回“加一个门就可能是新方法”的想法。SkillEvoReg 已有候选定向反例，VALVE 已研究长期验证门与复用面板的界，ACES 已进行有无技能的成对试验。更值得做的是核查这些保证所依赖的条件：任务是不是相互独立，同一仓库的近似任务是否被当作许多新样本，失败和未载入情况是否被排除。这是待验证的问题，不能预先宣称既有方法失效。

因此，后续验收至少要留下三种不同的对象：判据真正读到什么、在原本正确的情形上损失什么、这项结论经过多少次有反馈的选择。前两种可用配对回放核对，第三种要保存完整过程并另留确认材料。若固定任务上的简单检查已经足以覆盖承诺，就不应为了形式齐全增加审查轮数；若保证依赖不可检查的历史，则如实保留不知道的部分。下一次回访将优先寻找独立新任务和明确负控，而不以旧观察被重复引用增加置信度。

作用机制：生成者能利用检查反馈继续搜索；只有测到实际曝光、旧成功的损失及选择后的独立确认，才能分别识别未使用、回归和筛选偏差。

反证/替代解释：固定硬规则也可能误拒合法实现；规则家族的收益不等于开放任务能力。种子溯源的历史缺失和随机试验的选择偏差机制不同。VALVE等已有工作已处理部分自适应风险，必须核对其假设再谈缺口。

少一轮审查，还要看工作在哪里结束

10月13日的旧判断把生成、审查和交付分开，是因为企业流程研究与一家团队的审查自报给出了不同方向。前者记录代码和PR增加、合并等待变长，却未见事项完成显著增加；后者说能运行复现的机器人缩短了合并等待。PR是一次拟合入代码库的改动，等待包含排队、检查和返工，不能直接翻译成工程师劳动时长。周报重新检查这个问题，仍不把两份不同设计的研究当作互相推翻。

周末补上的Claude团队案例，让“返工”有了更具体的产生方式。自动作者会落实审查建议，自动审查又在下一轮发现旧问题；没有新的真实需求，系统也能连续创造修改。停止规则因此是工作流程的一部分：先审完整改动，后续聚焦新差异，并避免重复提出同一发现。但轮数下降不是终点，若真实缺陷漏检、事故或事后修复增加，省下的只是前面的时间。

这使此前“审查会成为瓶颈”的表述需要保留两个方向。一方面，生成加速可能加重队列；另一方面，提供可检查证据、按风险分配人力与减少噪声，确实可能扩大审查容量。团队前后统计不能分离模型升级、改动组合和流程变化，却足以反对“AI审查只能增加负担”的绝对判断。下一步最缺的仍是同一批任务上，实际人力、缺陷发现和交付质量的共同记录。

本期独立发现的Mercor图谱把问题再往前移了一步：用什么任务来代表工作？它将所选评测题映射到美国职业任务分类，发现许多任务在这份索引中缺少题目。这个结果不能推出模型做不了这些工作，更不能直接变成岗位替代率。它的价值是让我们先问，采购或招聘判断引用的分数，究竟有没有测到协调、复核、异常接手这些环节。没有测到，与测过但失败，需要完全不同的补救。

这里也不能只保留一个醒目的覆盖缺口。作者对四个职业做任务等权重比较时，已有APEX办公任务评测题目的模型分数变化不大；这是真实的正面边界，说明换权重未必改变排名。但被纳入比较的任务仍只是部分职业活动。对已经测到的部分，平均可能相当稳定；对没有题目的部分，平均值再精确也不会自动产生信息。这两件事可以同时成立。

SWE-TaskFlow给出一个更窄、也更容易做对照的入口：保留最终代码目标和测试，只改变需求逐步到达的方式，再加入仓库问答。它提示我们，题目标签相同，实际交接条件也可能不同。一次写清需求的成本，可能由用户在评测外提前承担；分步给需求又可能增加往返和模型费用。Mercor的职业映射与TaskFlow不是共同实验，我据此提出的只是比较办法：覆盖应同时标明目标、可用资料和交接协议。

公开评论保留了另一种分歧。status_quo69担心，按需让模型搜索代码局部，不等于人形成了整体理解；csallen则相信测试、历史版本和模型解释能帮助恢复。两者是对同一流程的不同判断，没有提供可比恢复实验。若审查还承担团队知识传递，就需要另外测：作者离开以后，接手者能否定位新事故、修改假设并完成恢复。事故率暂时不升，不能单独保证这项能力已经保留。

我目前更愿意用一份交付记录来替代笼统的提效倍数：预先固定质量和时限，分别留下等待、实际判断、机器重试、误报引起的修改，以及交付后的恢复成本；失败也留在分母里。职业图谱可以帮助发现待补任务，却不能替代这些记录。若在相同质量下人力和返工一起下降，就应承认自动审查的收益；若只是任务被缩小或坏结果被推迟，就应修正收益判断。这个结论是本周的测量立场，具体改善幅度仍待独立对照。

作用机制：审查评论会触发新修改，从而改变到达率和返工；任务取样与需求交接又决定哪些劳动进入测量。排队变化、知识传递和模型能力不能混作同一机制。

反证/替代解释：低风险改动可能适合少量自动检查，高风险工作多审几轮可能划算；内部前后变化没有识别单项因果。Mercor索引不完整且标签和工时含模型估计，不能外推整个经济或中国招聘市场。

Cortex：先确认规则被读到，再判断是否值得留下

技术Skill EvaluationPaired EvaluationRegression TestingContext Management

编程 Agent 的说明文件常在一次纠正后越积越多，但一次成功不能证明新说明有用。Samuele Giampieri的Cortex把这些文件当作可检验的改动：技能正文需要Agent主动打开，规则可按文件路径自动载入，二者都属于包围模型的工具与指令环境，也称harness。它先保存修复前的仓库状态、用户请求和检查，把重复纠正变成可回放任务，再一次只提出一条技能或规则。

系统交替运行有无该候选的任务，记录正文是否进入上下文及是否触发，并分别看改善、净变化和最严重的单任务下降；已稳定成功的任务还有保护条件。删除旧说明也要作反向对照，不能仅凭字数多就删。在作者专门构造的仓库、Claude Haiku 4.5与四次独立演化运行中，四类规则任务的保留场景通过率平均增加55.0个百分点，95%区间为34.1至74.1；这不是普通真实项目的通用提升。

本周重新核对的重点是负控：植入的有害候选没有被保留，但一些从未被读到，另一些主要在原先失败的任务上初筛，未能证明系统会识别伤害。更强模型的增益较小，真实项目里重复纠正不足时也可能学不到东西。它提供了可追查的增删流程，仍不是已验证的通用技能优化器。

社会反响：本次两轮精确检索及项目Issues未取得同版本的独立复测；HF收录与作者仓库属于发现/原作者材料，不能按平台数增加可信度。

重要性判断：把指令曝光与任务效果分开，能改变团队增删技能的依据；合成仓库和弱模型条件限制外推。

发展判断：未来1–3个月观察真实仓库的重复纠正覆盖、已成功任务退步、未载入比例和独立复测；不能只看规则数量。

Claude Code团队：把审查噪声产生的修改算进成本

技术Agentic Code ReviewFalse Positive ControlRegression TestingRelease Engineering

Agent能连续写代码以后，团队还要判断哪些改动可以合入。Claude Code团队10月15日介绍的流程，把审查前移到写代码时：先展示测试、构建等执行结果，再由新上下文检查；提交给团队合并的一组改动称PR，进入PR后分别进行缺陷与安全审查，并按风险确定人类批准要求。合并队列、分阶段开放和回滚承担后续防线。

自动化也会制造工作。一项PR曾一夜经历五十多轮检查与修复；团队追查发现，反复提出的内容约59%在第一次审查时已经存在。于是限制轮数，随后集中看新差异，一次指出整类问题并抑制重复发现。这里改变的是作者与审阅者互相触发新修改的过程，不能仅用评论多少衡量质量。

为防止少审等于漏审，团队每天回放经工程师确认的历史事故，并让审查器检查已知干净的PR，记录可能诱发有害修改的意见。作者自报6月至9月合并PR翻倍以上、回滚占比下降超过40%，但多项机制一起改变，尚不能归因到某个模型或轮数限制。外部评论进一步追问：机器承担阅读后，人是否还保有接手故障所需的系统理解。

ECDSA曲线种子有了可重算的来历，选择历史仍有空白

技术Cryptographic Parameter ProvenancePRNG State RecoveryLattice ReductionReproducibility

ECDSA是一种利用椭圆曲线完成数字签名的方法。不同实现使用标准公布的曲线参数才能互通，但2000年NIST标准中的一批生成种子没有说明最初怎样产生。过去查找曾沿“幽默短语的哈希”展开；Anthropic团队10月16日报告，内部研究模型改查1990年代程序常用的伪随机数生成器。伪随机数由有限内部状态决定，输出中残留的结构能帮助倒推状态。

方法先从部分种子的高位规律识别C库lrand48，并枚举隐藏位核对连续输出；另一批仅取每次输出的高字节，则用LLL格基约简——一种寻找整数关系的算法——恢复被截去的信息。把状态逆推到初始化形式后，十个素数域曲线种子对应1997至1998年的时间戳。P-256对应其中一次初始化的第1842个候选，公布的短程序可重算种子。这里找到的是生成关系，没有报告签名被破解。

仍需区分“能生成它”和“当年为什么选它”：同一次P-256运行里更早的第876个候选也满足作者列出的条件，却被跳过，原因未知；B-163种子及部分基点来源也未解释。HN评论一方保留弃选历史的疑问，另一方反对据小规模搜索推断存在弱曲线。两种意见都不构成新攻击证据。

社会反响：同一HN讨论出现对参数来源、弃选历史和弱曲线数量的具体分歧，显示该技术社区的关注；未以13:00之后变化的分数或评论数衡量反响，未取得独立攻击或完整历史材料。

重要性判断：把长期传闻转成公开可计算关系，具有方法启发；安全解释必须与仍未知的选择标准分开。

发展判断：追踪独立重算、当年筛选标准、B-163及其余基点解释；只增加热度而无实质材料不提高新颖性。

候选创新点 · 查新风险 高

在相关任务上校准技能验收的误收率

问题：保持总验证调用预算不变，当任务来自同一模板或同一缺陷家族时，反复选择技能的实际误收率是否超过按任务数估计的水平？

假设：在预先构造的零真实增益候选上，把同模板任务当独立样本将低估误收；按任务家族分组、限制反馈次数并留一次独立确认，可使整轮错误采用比例至少下降一半，同时保留至少80%的有益候选。两项阈值都是拟议标准。

为何可能新：不主张首次研究验证集复用、反例或长期门。候选贡献是一个固定预算、候选数×任务相关性的交叉压力试验，校验现有门的经验适用范围；分组确认是待比较的工程策略，不宣称新统计定理。若近邻已有同一交叉对照，撤回机制新颖性，仅作复现。

最小验证：4–6周。取3个可本地重建的小型开源仓库，每库设计20个独立缺陷家族并为每家族构造近似变体；由维护者先验确认有效、无效和有害规则。固定模型及曝光方式，比较10与40次带反馈选择、低与高任务相关性，至少5个独立选择种子。各方法分配相同总验证调用上限；调用不足记未判定，不补成通过。选择后一次运行封存的新家族任务，按仓库/家族聚类分析。先用小试估方差，若无法达到预注册精度则停止而非报告“无差异”。

证伪方式：若原门在相关性与查询次数增加后仍保持预定误收上限，或分组确认不能在相同预算下降低误收，假设不成立；若只是牺牲超过20%的有益候选或大量拒判获得低误收，工程目标也失败。

伦理/滥用：只用有许可的本地仓库与隔离任务；不接生产权限，完整保存失败，实验日志不含凭据。

候选创新点 · 查新风险 高

将干净PR的误报转成执行后的净损害测量

问题：两个审查器的错误评论率相近时，能否因建议可执行性不同，对同一自动作者造成不同的回归和修复轮数？

假设：在干净PR与带缺陷PR的配对集合上，要求审查意见附可复现证据并区分原有/新增问题，能比单纯提高投票阈值减少至少30%的误报诱发回归，同时真实缺陷修复率下降不超过5个百分点。阈值是预注册目标，不是已有结果。

为何可能新：干净PR已见SWR-Bench与DiffDojo，执行审查建议已见c-CRAB，均不是本次发明。拟新增的是在同一组PR上固定评论后随机执行/不执行，直接估计误报诱发的功能损失，并比较人和Agent的处置成本；不是把两种已有评分简单相加。

最小验证：4–6周。选60份经两位审阅者及保留测试核对的干净PR，再配60份同规模、同模块的可验证缺陷PR；测试通过不直接等于干净，分歧样本另列。冻结一个自动作者及两个审查配置，先生成并封存评论，再为同一评论建立执行与不执行分支，各至多3轮。用独立保留测试与盲审核对新回归；20份样本加人工处置计时。所有失败、拒修和未收敛分支计入分母。

证伪方式：若证据要求仅减少评论但不能降低执行后损害，或降低损害的代价是缺陷修复率越过5点劣化界，假设失败。若干净标签无法可靠复核，停止因果比较，先发布标签缺口和复现材料。

伦理/滥用：在可撤销的隔离副本中执行建议；人审参与者事前同意并按时间付费，不公开可识别个人工作表现。

比较基线：c-CRAB式建议执行与缺陷测试；SWR-Bench式干净PR误报；固定投票阈值。与带复现证据的意见在相同模型和审查预算下配对比较。

SWR-Bench（2025）：平衡Change/Clean PR：继承干净与有问题样本的平衡和人审；由评论层误报进一步测固定自动作者执行后的净损失，且保留不执行分支。

用同一任务的不同交接版本检验覆盖图稳定性

问题：最终交付目标和测试保持不变时，把完整需求拆成逐步交接，是否会改变基准到职业任务的映射与模型完成率，而且两种变化方向并不一致？

假设：至少20%的成对任务会在职业标签数量或覆盖判定上变化，但这些表述变化不能稳定预测实际成功变化；在映射中明确必需资料、交接动作及验收对象，可使标签不一致比例至少下降三分之一。均为待测目标。

为何可能新：不再制作一份职业排行榜，也不主张首先测试多步任务。拟检验覆盖映射对任务表述与交接协议的可控敏感性：同一终态的三个版本只算一个任务家族，并把映射漂移与真实能力变化交叉分析。它比“加权重排榜”更窄，新颖性仍有重叠风险。

最小验证：3–5周。取40项代码任务与40项可本地复建的办公流程，每项做完整单次需求、分步交接、分步交接加一次约束澄清三个版本；由两位标注者确认最终目标与测试一致，不编造真实企业案例。使用两种映射模型、两种执行模型；数据按原任务家族分开。比较逐题映射与带必需条件的映射，再把版本级映射差和完成率差分开报告。先试验10家族，若终态无法保持等价则停止扩大。

证伪方式：若原映射在等价版本间已稳定，或改进方案只是把真实不同的交接需求抹掉，假设失败；若控制标注者分歧后变化消失，不把它解释成模型能力缺口。发现近邻已有相同干预实验时，只保留复现价值。

伦理/滥用：使用公开有许可任务与合成等价变体，不使用企业私有数据；职业分类不用于评判具体求职者或推断个人能力。

最近邻工作

  • Mercor Benchmark Map（2026）及方法

  • SWE-TaskFlow（2026）
  • WorkArena++（2024）

科研 / 工程价值：职业覆盖图会参与模型采购和选题。即使某项职业标签不变，约束何时出现、需要人补多少材料仍会改变工作量；先做敏感性试验可定位该补任务还是补接口。

比较基线：Mercor式逐题O*NET映射；Wang等的领域/活动分层映射；SWE-TaskFlow的分步需求协议。保持相同目录版本、映射模型和任务集合，不与另一套题目换榜比较。

成功指标：主要指标为同家族标签集合的交并比（Jaccard）差异、覆盖门槛跨越率、人审一致性；能力侧另报最终测试成功、用户补充信息量、往返和总成本。不能用提高标签稳定性代替保持真实差异，新增必要交接也须被识别。

Mercor Benchmark Map（2026）及方法：已有职业覆盖、标签与权重比较；本候选不重算全经济比例，只对同一交付目标的协议版本做配对敏感性试验。

Wang等（2026）：Agent开发与真实工作：已有分层职业/活动映射及工作流复杂度；拟固定原任务终态，干预信息到达和澄清条件，分开映射变化与执行变化。

SWE-TaskFlow（2026）：已保持测试并拆分需求、插入问答；在其协议上增加职业映射不变性和多对一计数检查，不声称分步任务是新设计。

WorkArena++（2024）：已有复合办公任务和复杂度层级；只借其可执行工作流，不把更多步骤当更多独立职业任务。
