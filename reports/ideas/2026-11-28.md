# 三个研究入口：记忆容量、验证计算与技能迁移

2026-11-28 · 独立研究笔记

本期独立检索整个知识库，不限于周报的四项精选。我们比较了十个方向的资料入口，再深入循环记忆、推理系统和机器人表征，选出三种不同的下一步：解释训练内部机制、比较部署约束下的工程方案，以及更新已经等待代码的复现问题。

它们共同要求先把中间指标和最终用途分开：状态稳定不等于信息能读回，少算几行不等于请求更快，视觉预测知识也不等于新的动作技能。但三者的对象、工具和证据不同，不能合并成一套算法。正文分别说明已有工作、为何联系、值得继续追的问题和起步入口；没有按“新颖”标签宣称首创。

先读循环记忆的受控回放方向，再看固定后端上的推测解码比较，最后回到 DreamFree 的代码发布。所有方案尚未在本期运行；取得论文或检查点只改变可继续核查的条件，不代表研究假设已经成立。

## 状态不再爆炸以后，记忆究竟保住了多少

可做机制复现；尚未运行 · 循环记忆 / 线性注意力 / 机制复现

用可控的键值回放区分数值稳定、状态容量和信息读回，避免把训练没有崩溃当作长记忆已经可靠。

### 他们已经做了什么

Stable Gated DeltaNet-2 研究固定大小循环状态为何会在长序列上失稳。原 GDN-2 擦除时读取与修改的方向不对称，连续更新可能放大状态，即使后来不再写入新内容。论文将门控对称施加到两个键因子，并控制残差写入的强度；作者的128K检索成绩从4.82升到11.62，绝对值仍低，主要训练比较只有一个种子。

另一条已有线索 On State Reduction in Linear Attention 研究预训练循环状态的低秩结构，提出对键和查询矩阵做结构剪枝，在其条件下缩小状态仍能保留较多能力。本次只读其摘要与版本页，没有核对完整剪枝实验。前者提醒“某个方向被异常放大”可能挤占有效容量，后者提醒“数值维度很多”也未必意味着都在有效使用；二者不是同模型的直接对照。

### 为什么把这些线索放在一起

库内 Stable GDN-2 材料已经提出稳定与信息读回要分开判断；回看“训练帮助要看学生接下去做了什么”，可以把结果检查落到使用者真正需要的动作：过了很久以后，是否仍能找到先前写入的特定关联。状态范数正常只是中间条件。低秩研究提供相邻问题，但不能仅凭两篇论文就断定低秩一定是故障；有些低秩来自数据结构，有些可能来自异常放大。

### 可以往哪些方向走

一个值得探索的方向，是用同一组受控键值序列回放原更新与稳定更新，分别改变相关键的数量、间隔和相似度，观察状态范数、有效秩（信息分布在多少个独立方向）以及目标值能否读回。暂停写入可以检验传播本身，继续加入相似键则可暴露干扰；两种输入回答不同问题。若稳定后读回仍随信息量迅速下降，后续应优先研究容量和干扰，而不是继续只做数值裁剪。

这不是重新训练1.6B模型的要求，也不是宣称一种新记忆算法。先把论文机制缩成小规模可解释实验，再决定是否需要训练级对照；减少维度的剪枝结果只作为待比较线索，需补读全文才能选择公平基线。

### 值得做在哪里

价值在于让长上下文失败的处理有明确去向：数值失稳、有效容量缩减和任务检索失败需要不同修复。工程监控也可先看内部状态，而不等最终损失异常。若回放中所有读回变化都能由范数解释，这个设想的额外价值就有限；若同样稳定的状态仍有明显不同的记忆表现，才值得继续追问表示和更新规则。这里陈述的是判别条件，尚无本期实验结果。

### 从哪里开始看

先读 Stable GDN-2 的不写入回放、对称擦除推导与长上下文结果，再看其引用的 GDN-2 实现。用几十维的合成关联检验自己是否理解更新式，随后补读状态剪枝论文的实验与代码。库内11月28日报保留了训练规模和低绝对成绩，可作为回看入口；不要一开始把总训练规模搬到自己的设备。

### 暂时不往哪里走

本期未运行代码、未验证定理，也未确认此复现切口在全部相关文献中的新颖性。

## 验证形状不能变时，还能省掉多少草稿尾部工作

可做工程比较；尚未运行 · 推测解码 / vLLM / 混合专家 / GPU分析

比较动态验证预算与固定形状内跳过专家计算的适用条件，将吞吐优化落实到实际后端、采样方式和维护成本。

### 他们已经做了什么

Runtime Notes 在单台128GB GB10上运行 Inkling 2 Mini，保留长上下文及另一模型常驻但空闲，报告单请求约101 tok/s。它把草稿尾部低概率位置标成填充，保留八行验证形状，同时跳过这些行的专家读取；切断位置由累计草稿概率决定，可接受长度也随之受限。作者的端到端收益小于离线预测，显示算子时间估算不能直接替代完整运行。

vLLM 的 Adaptive Verification 已经按预计存活概率，在不同请求的草稿位置间分配全局计算预算，并用启动时测出的成本模型选择预算。文档要求后端支持设备决定的查询长度与完整 CUDA 图，也列明 LoRA、流水线并行等限制。Runtime Notes 说明自己的 Inkling 后端不支持所需动态验证形状，因而采用固定形状内少做工作的方案。两者解决相近浪费，但适用接口不同，不应把后者泛称为首次提出自适应验证。

### 为什么把这些线索放在一起

全库旧资料已经记录 vLLM 自适应验证和接受率估计器；本周 GB10 经验增加了一个现实限制：理论上能减少 token 数，现有后端却未必允许改变计算形状。把两者放在一起，机会在兼容条件与实际成本的比较，而不是再造一套同名调度。该方向不依赖本周周报的四项精选，也与循环记忆的训练稳定问题不同。

### 可以往哪些方向走

可以沿实际部署的后端先区分两种路径：支持动态长度时复用上游机制；不支持时评估固定形状下跳过专家工作的收益及正确性边界。比较时保留相同模型、提示、输出长度、采样分布与并发，再分别查看草稿成本、被拒绝尾部读取和总请求时间。温度0与温度1应分开，因为作者的概率采样改动在两者中收益不同。

进一步的工程问题是阈值是否应随负载和工作类型调整。代码、计数等容易预测的序列可能被过早截断，短期节省验证计算却丢掉本可接受的 token。需要把这种损失与跳过的专家读取一起计入，而不是只优化单步速度。这里提出比较方法，没有在本期部署补丁。

### 值得做在哪里

适合已经受固定后端或统一内存容量限制、无法任意换引擎的使用者。它可能提供比整套迁移更小的优化入口，也可能证明维护补丁不值得：作者覆盖层绑定版本和源文件哈希，升级需要重新检查。若上游后端已支持动态路径，优先复用它；若多请求吞吐或长提示首 token 时间退化，单请求峰值也不足以支持采用。

### 从哪里开始看

先读 GB10 原文的固定形状示例和端到端差异，再对照 vLLM 文档的后端、CUDA 图和成本画像限制。手头没有 GB10 时，可先复查两种策略的接口条件和公开日志，不能据此声称复制了101 tok/s。真正开始实测时，应先保存未修改版本的可重复负载与输出检查，再评估优化和版本维护代价。

### 暂时不往哪里走

未运行模型、未验证补丁或采样分布；另一常驻模型空闲不代表双模型同时工作。

## DreamFree 代码已发布：先分清学到的是新组合还是新动作

更新旧方向：从等待代码进入实现核查；尚未复现 · 具身智能 / 未来表征蒸馏 / 动作扩散 / 复现

利用已发布编码器、动作策略和来源信息核查冻结边界，先厘清组合视频怎样影响旧动作的使用，再讨论新技能。

### 他们已经做了什么

DreamFree 用能看见当前及未来画面的冻结视频教师，训练只看当前画面的学生表征；部署时省去生成未来视频，但动作模型仍通过扩散产生动作块。视觉表征训练和带动作标签的策略训练是不同阶段。11月7日旧 idea 报还在等待代码，当前仓库已列出11月10日发布的 LIBERO、RoboCasa、DROID 检查点，包含视觉编码器、动作策略、归一化统计与来源信息；单阶段端到端训练仍写着待发布。

本次重读项目页，组合微波炉任务仍报告：增加组合视频后，成功率由0%到5%，进度由8.8%到26.3%，原子动作仍有动作标注。本地提取最初只有表征蒸馏说明，随后经另一公开读取路径补到了任务对照：两组使用相同原子动作标签，新增的是组合视频。这里仍只是核对作者公开结果，没有运行实验或逐帧观看演示。当前 README 的检查点布局，则提供了可以进一步核查训练边界的实际入口。

### 为什么把这些线索放在一起

旧方向问：预测未来的视觉特征，究竟帮助选择已有动作，还是带来了没有动作示范的新技能？代码发布改变的是问题的可操作程度，没有回答问题本身。库内关于训练支架的观察也提醒我们，先问待学习的关键动作是否已经藏在标签或起点里。把这条原则用于 DreamFree，需要追到哪些参数冻结、哪些数据含动作，以及组合任务用了哪些原子技能，不能从“无动作视频训练表征”跳到“整个机器人不需动作标签”。

### 可以往哪些方向走

先选择已有模拟基准的公开检查点，核对加载器是否确实按发布说明组合编码器、读出模块、动作策略与归一化统计，再复现作者原设置中的一个行为。随后才考虑保持动作数据和动作策略训练条件一致，只改变是否加入组合视频，分别查看组合顺序改善与新动作能力。若收益只出现在已见原子动作的新排列，结论应收窄为组合利用；若要主张新动作迁移，还需要目标动作从未出现在动作监督中的清楚对照。

实现中的读出模块将视觉特征变成动作条件，它与蒸馏时对齐教师特征的投影模块职责不同。复现时把两者及冻结边界画清楚，比先追最快延迟更接近这个研究问题。本地请求一度失败，随后补读的架构文档明确：Stage 1投影器用于蒸馏，不进入动作策略；Stage 2读出模块把冻结视觉特征变成动作条件。这是文档核对，仍不是全部源码审计。

### 值得做在哪里

这一切口能帮助机器人研究者判断，视频数据增加的是环境预测知识、技能组合机会，还是新的控制技能。若只是更好调用旧动作，也仍可能减少组合任务的数据需求；但这与完全从视频获得新技能的价值和限制不同。已有模型包降低了入口成本，仍需要合适 GPU、模拟器和动作接口，远非下载权重即可证明迁移。

### 从哪里开始看

从仓库 README 的 Model Preparation 与评估入口开始，确认 release 中 stage1、stage2 和 provenance 的关系，再补读方法和评估文档。本期沿用项目原图解释“教师看未来、学生部署只看现在”的结构；图不是当前源码一致性的证明。首先复现一个公开设置，再用受控变化回答旧问题；不从 DROID 实机和完整14B训练起步。

未下载检查点、未运行模拟器、未进行实机操作；只更新材料可用性与研究入口。
