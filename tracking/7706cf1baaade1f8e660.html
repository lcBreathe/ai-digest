MICA：能力相同，MCP 与命令行仍会改变 Agent 的选择

按时间保留当时的判断和后续核查；历史收录不代表刚刚重新验证。

2026-10-31 · 当时的记录

给 Agent 接上相同工具，就能公平比较接口吗？MICA 研究的是更严格的问题：可执行动作、参数和环境状态保持一致，只改变模型看到和表达这些动作的方式。MCP（模型上下文协议）在这里呈现具名工具与结构化参数；CLI（命令行接口）呈现命令和参数文字。两种输出都被解码成同一语义动作，交给共同的校验与执行过程。

作者在六个模型、三个交互环境中比较它们。家庭任务 ALFWorld 中，Qwen3-14B 的成功率从 MCP 的20.1%变为 CLI 的56.7%；购物任务 WebShop 中却是 MCP 的64.4%高于 CLI 的59.5%。结果没有给出一个处处更好的接口。2,004对轨迹中，94.3%出现有后果的结构性分歧；这个比例表示执行过程不同，不是失败率。

论文还在同一个决策状态下分别改变能力说明、动作表达和反馈形式，观察局部差异如何进入后续历史。由此提出 DART：先校验想执行的动作和参数，若意图有效、只是接口表达出错，就固定这个决定，只修表达；不能维持有效承诺时，交回普通策略重新处理。

DART 的收益来自 Gemini-2.5-Flash 在三个环境乘两种接口的六个设置，而非六个模型都验证过。各设置得分增加0.8至9.0个百分点；MCP 的 token 消耗均下降，CLI 两个环境反而增加。它提供了一个清楚的修复边界，收益和成本仍依赖具体场景。
