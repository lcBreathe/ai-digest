浏览器代理面对的困难往往不是少一个点击按钮，而是页面卡住、信息藏在脚本里，或需要把多步动作组织成一段程序。browser-use 1.0 于11月10日发布，团队11月20日补充解释：把主要操作放进持续存在的 Python 会话，提供浏览器底层 CDP 命令和辅助函数，由模型组合执行。CDP 是程序控制浏览器的协议，可以操作页面、网络和运行状态；文章列出一个主要 Python 工具及两种结束方式。持续会话会保留变量与程序状态，让一次探索可以成为下一次操作的起点。

作者的例子是抓取一个卡住的股票页面：代理停止加载、屏蔽阻塞脚本，随后从页面脚本中找到数据接口，再批量请求所需日期。值得借鉴的是模型可以在界面操作与程序化取数之间改变方法。文章报告在其冻结任务集上，相对旧系统的分数提高14—33个百分点，模型费用下降2.7—5.2倍；这是整个运行时变化后的作者比较，未单独证明减少工具数量造成了提升，费用也不是全部服务成本。

同日另文讨论的是 Claude Code 评测适配器的一次改动，不能和上述新版对照混为一项实验。它初看提高5.1分，后来发现旧裁判只读 FINAL ANSWER 标记之后的文字。团队将200条旧运行的完整答案重评，基线就上升2.6分；相同证据原样重评也有0.8分波动。作者据此将错误贡献估为1.8—2.6分，剩余代理变化的区间包含零。这一自查说明留存答案、轨迹和配置能帮助拆解提升，但新版裁判尚无人类标签校准，不能把修复输入等同于判分已经准确。

browser-use 是让语言模型操作浏览器的开源工具。旧版把点击、输入等动作预先封装成一组工具；网站出现未预料的情况时，模型即使知道该做什么，也可能找不到对应动作。11 月 20 日的工程文章解释了 1.0 的改造：把 24 个浏览器动作入口收拢到一个持续保留变量的 Python 执行环境，另有结束任务的工具。模型可以写代码，通过 Chrome DevTools Protocol（CDP，浏览器调试控制协议）组合操作，也能使用预置辅助函数。

文章给出的例子是股票数据页面卡住。代理先停止加载、检查页面，再阻断卡住的脚本并重载；随后从网站脚本找到数据接口，分批请求，重试失败批次。这里的收益不只是少选几个工具，而是能把“检查原因—改变加载方式—直接取数据”连成程序。模型不必等框架开发者先为每一种例外添加专用按钮。

作者在 BU Bench v2.1 的固定的 180 任务计分子集上，对同样三种模型各运行一次，报告完成度提高 14–33 个百分点、模型费用降至原来的约 1/2.7–1/5.2。这是整套版本的自报比较，不能把全部变化归因于入口数量。1.0.0 实际发布于 11 月 10 日；默认浏览器、步数上限和运行时也有变化。发布说明另有一组对照，扣除服务商故障后质量差异并不显著，不能把两组测试混成同一个成绩。
