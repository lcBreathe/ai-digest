2026-10-31 · 当时的记录

Skyvern 是把网页操作交给模型的开源框架，面向取发票、填表和跨页面办事等任务。旧版先截图、标注并提取可交互元素，再把压缩后的列表交给模型。这个做法减少了模型面对的复杂度，却把成败绑在预处理上：Shadow DOM、iframe 和复杂控件里一旦漏掉目标，后面的推理能力无法补回一个根本没被展示的按钮。

团队参考 Pi 重写工作流，允许模型用生成的 JavaScript 扫描 HTML、调用浏览器动作、需要时截图，并主动结束任务。原文把这称作删除 RAG，但这里删除的是固定前置的网页抽取流程，不是证明所有文档检索都无用。信息仍然要获取，只是获取什么、何时获取更多地由任务过程决定。

作者报告，约十万次客户运行的生产 A/B 中，平均耗时从593秒降至262秒，每次总成本从0.039美元降至0.0302美元。调用轮次从6.4增至23，总 token 从18.8万增至28.6万；与此同时，带截图调用占比从27%降至2.7%，缓存命中率从27%升至79.7%。它说明计费结构与上下文复用足以改变“更多调用一定更贵”的直觉。另一个实验是 Odysseys 公共基准上的90.5%完美评分成功率，不能把它当作上述客户运行的成功率。

文章首次发表于10月1日、6日更新，本周因讨论和日报重新进入视野。现有证据是团队自报的架构整体比较，未充分披露生产分组、任务构成和置信区间；它足以提示排查瓶颈，却还不能把2.3倍提速全部归给“去掉RAG”这一项。

2026-10-26 · 当时的记录

Skyvern 是执行网页操作的 Agent。旧流程每轮先生成带标注的截图，再解析页面、筛出可能有用的元素交给模型。这样做看似节省输入，却把预处理器变成了信息入口：隐藏在 Shadow DOM、内嵌框架或特殊控件里的内容若没被提取，后面的模型再强也看不到。

团队改成让模型按需取信息。它可以生成 JavaScript 读取页面，调用浏览器动作工具，必要时截图，最后结束任务。原先每轮固定准备的材料，变成执行中主动选择的工具结果；能用页面结构解决时，不必总传图像。

作者报告约十万次生产运行的 A/B 比较：平均耗时从593秒降至262秒，每次成本从0.039美元降至0.0302美元。与此同时，平均模型调用从6.4次升至23次，总 token 从约18.8万升至28.6万；缓存命中率从27%升至79.7%。更多小轮次可以复用已有前缀，较少的单轮输入也降低等待，因此总量增长与账单下降并不矛盾。

这是整套执行方式重构后的作者自报结果，不能把全部收益单独归给“删除 RAG”。文章另列的 Odysseys 基准成绩来自另一项测试，不能充当这十万次运行正确率不变的证据。文章发布于10月1日、6日更新，本期由近期讨论重新发现。
