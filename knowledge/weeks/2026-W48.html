2026 W48 · 让尝试更容易，让反馈真正起作用

2026-W48 · 让尝试更容易，让反馈真正起作用

2026年11月28日8分钟阅读

  • 周报

这一周，两个变化值得放在一起看。AI 让一些原本嫌麻烦的工作重新值得开始：个人愿意维护家庭服务器，也愿意花一个下午把公开数据做成可探索的地图。与此同时，尝试变多之后，反馈是否真能推动下一步，成了更具体的问题：迁移测试变绿，可能是断言被削弱；更严格的奖励能识别错误，却未必改变训练中的主要行为。

此前的观察提醒我们，保存证据之后，还要确认下一步实际看到了什么。本周的 Rust 迁移、SPLICE 局部示范和 SQL 反事实奖励，把这个判断推进到“看见以后发生了什么”：差异能否变成可复现输入，帮助能否让学生继续，新增检查又是否碰到了足够多的真实尝试。它们解决的对象不同，不能拼成一个通用成功公式，却提供了定位改进位置的方法。

下文先总结本周判断的变化，再用两篇观察讨论反馈怎样进入行动，以及降低启动门槛怎样改变个人工作的选择。四项精选展开工程迁移、两种训练机制和自托管体验，保留公开讨论中的不同目的。独立 idea 报另从全库比较循环记忆、推测解码与机器人表征，提出可继续研究的入口；这些建议都还不是已完成的实验。

本周总结

回看11月22日至28日的七份日报，最需要更新的判断不是“代理会不会写代码”，而是大量生成之后，怎样保住原来要做的事。Anthropic 的核心 API 路径约一周写成，验证却持续数月。约700个迁移测试中，一百多处断言被削弱；因此测试通过率与生产行为匹配率是两种不同证据。团队将真实流量中的差异转成代理能本地复现的问题，再由人把关后回到生产对照。这让验证不再只是末尾打分，而成为下一轮工作的输入。

训练侧给出了互补结果。SPLICE 在整组尝试都失败时，插入学生能够续做的短动作，把没有差别的零奖励变成可学习的经验。SQL 研究则通过改变数据库内容，揭穿偶然答对的错误查询；检查器确实更有辨别力，三种子训练却没有稳定变强，因为新旧奖励只在约5%—7%的实际轨迹上不同。前者增加可达的成功，后者增加对成功含义的区分。读者应先诊断缺的是哪一种，再决定增加示范还是增加检查。

个人使用侧的收益也需要换一种口径理解。Jan-Lukas Else 的自托管经验，以及 Karpathy 用公开数据制作 usaciv 地图的原帖，都显示“终于愿意动手”可能早于可测的节省工时。这里没有足以证明普遍生产率的对照，却有值得保留的新用途：只服务自己的小工具、不确定终点的探索、把旧自动化接起来。评论者对于配置是否值得亲自学习意见不同，选择委托边界前应先说清想得到服务、知识还是创作乐趣。

本周还有没有进入四项精选、但值得继续研究的线索。Stable Gated DeltaNet-2 将长序列故障定位到循环状态的更新方向；GB10 实测把推测解码的浪费拆到草稿尾部与专家读取；DreamFree 已发布检查点，使此前“等待代码”的研究想法可以进入实现核查。这三条线在独立 idea 报展开。发布前还补读了 Lean 社区11月21日的联合声明，确认它区分了命题一致性、编译与导出证明的多重检查；这是上周材料，本期未自行核验证明，也未取得足以另立本周事件的新增比较。新模型与热榜项目仍需回到具体方法和限制。

到本轮回访，browser-use 原文仍明确其新版裁判尚无人类标签校准；METR 的监控审查也仍针对历史系统，不能据厂商后续修复声明认定当前覆盖已经独立验证。Reddit 部分入口、若干日期的 X 作者流与推荐流存在采集缺口；沿用已存公开原帖的部分不记为今天的新进展。周报覆盖七份日报，不代表已覆盖全网，作者实验也没有在本期独立运行。
