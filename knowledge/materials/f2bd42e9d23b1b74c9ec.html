Modern Web Guidance 1.0：把浏览器知识交给代理，也把适用条件写清楚

2026年11月11日7分钟阅读

  • 工具与产品

Chrome 开发者团队与社区 · 阅读原文

原始来源：Chrome 开发者团队与社区

发现渠道：Hacker News

编码代理能写出可运行的页面，却常沿用较旧的 JavaScript 方案：自己管理弹层焦点、编写滑动手势，再补一串边界处理。Modern Web Guidance 把浏览器工程师和无障碍专家维护的指南按用例提供给代理，并附兼容数据，让它在动手前知道哪些原生 HTML、CSS 功能可以接管这些工作。11月10日的1.0版还加入了对既有代码的现代化扫描。

导航抽屉指南给出了一个实际取舍。如果面板永远只作抽屉，可以采用原生 dialog，让浏览器提供模态、焦点恢复等行为；如果同一元素在宽屏还要变成普通侧栏，就不能始终把它声明为对话框，可以使用 popover，但需自行补足模态处理。滑动也可以交给滚动吸附，而不是自己重写每次手指移动。这些知识帮助代理选择实现路径，并非单纯告诉它多用新 API。

1.0 的扫描器只查一组已知静态模式，不等于全面审计。官方公布的客户案例包括 note 的180次运行中，现代 Web 检查通过率从61%升至94%；这是项目方报告的特定检查结果，不是所有网页质量都按相同比例改善。指南明确要求结合运行时调试：例如建议可以解释怎样切分长任务，实际是否仍阻塞主线程，要另做性能追踪。

编辑评读

它解决的是一种容易被误判成“模型不够聪明”的问题：代理缺少最新且带使用条件的领域知识，就会用熟悉的旧办法绕远路。这里的改进单位是可维护的用例指南。抽屉与侧栏的例子尤其有用，因为两个视觉相近的界面需要不同语义；把截图做得相似，不能替代键盘、焦点和辅助技术下的正确行为。

HN 的分歧提醒读者，现代不等于所有目标浏览器已经支持。一个保守的扫描器只报告少数确定模式，可能避免无意义改动，也可能漏掉许多问题。因此应分别评价指南的建议质量、扫描覆盖面和最终运行效果，不能用“只发现两处”证明整套指南无用，也不能用安装了指南证明应用已达标。

实际采用时，可先给代理明确的浏览器版本范围和组件用途，再检查生成方案的兼容表与退化路径。挑一个真实组件观察键盘操作、减少动画偏好和低性能设备下的行为，会比对比代码行数更接近用户价值。本期读了指南与案例，没有运行其安装器，也没有重测客户宣称的增益。
